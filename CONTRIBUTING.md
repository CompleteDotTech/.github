# Contributing

Thanks for your interest. These defaults apply to public repositories on the CompleteDotTech account unless a repository has its own `CONTRIBUTING.md`.

## Original work or fork?

Most public repositories here are forks of upstream projects. If your change is to upstream code or behaviour, send it to the upstream project; a fork here will not carry it back. Original repositories, such as `buffons-match-lab` and `paper-package`, are the ones where changes are welcome.

## Before you start

- Read the repository README for what the project does and what it does not claim.
- For anything beyond a small fix, open an issue first so we can agree on direction.
- Some repositories contain byte-pinned evidence (hash manifests, recorded validation runs). Do not edit those files; open an issue instead.

## Making a change

1. Fork the repository and branch from the default branch.
2. Keep the change to one concern.
3. Run the checks the repository documents and say what you ran and what passed.
4. Open a pull request describing what changed and why.

## Ground rules

- Do not commit secrets, credentials or personal data.
- Do not claim results or features that you did not verify.
- Contributions are distributed under the repository's licence; licences vary by repository, and some repositories do not state one.
- Participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md).

Reviews are best-effort and may be slow. Security problems go through [SECURITY.md](SECURITY.md), not a public issue.
